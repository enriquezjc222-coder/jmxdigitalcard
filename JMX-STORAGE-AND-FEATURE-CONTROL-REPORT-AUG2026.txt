CLOUD STORAGE ARCHITECTURE
- New images/PDFs are uploaded to Firebase Cloud Storage under:
  cards/{cardId}/{mediaId}/{unique-filename}
- Firestore profile documents store a small media manifest containing URL, storagePath,
  filename, MIME type, size and timestamp metadata.
- New cards are created with mediaStorageVersion: 2 and media: {}.
- Public/profile editor loading uses the Storage manifest first.
- Existing legacy cards that still use cards/{cardId}/media Base64 documents remain readable.
- Legacy media is not bulk-deleted or automatically destructively migrated.
- When a user explicitly replaces/removes a particular media item, only that item's old
  representation is cleaned up after the new Storage upload succeeds.

STORAGE SECURITY
- Public read is allowed only under the public-card media path because these assets are
  intentionally displayed on public JMX profiles.
- Upload/update/delete requires either the JMX admin UID or the owner UID from cardOwners.
- Uploads are limited to images/PDF and less than 12 MB by Storage Rules.
- All other Storage paths are denied by default.

FEATURE CONTROL HIERARCHY
- Public card effective permission:
  Global control -> Plan control -> Client-specific admin override -> Client visibility choice.
- Client editor effective permission:
  Global control -> Plan control -> Client-specific admin override.
- A feature disabled by JMX administration is hidden from the owner's editor, not merely disabled.
- Its public-card UI is also hidden.
- Hidden controls use normal document layout so no placeholder gap is reserved.
- Saved client data is preserved when a feature is administratively disabled.

CLIENT-SPECIFIC FEATURE OVERRIDES
- Each client's large admin detail dialog now includes Client Feature Overrides.
- An OFF switch hides that feature only for that client, both publicly and inside that client's editor.
- Global and plan controls have priority and cannot be bypassed by a client-specific switch.
- Overrides are stored on cards/{cardId}.featureOverrides and are admin-write-only under existing Firestore rules.

FIRESTORE COST/READ OPTIMIZATION

- Their media URLs arrive with the normal profile document.
- Legacy cards keep the old query only while they remain legacy, preserving compatibility.
- Analytics write behavior was intentionally not changed because exact metrics were requested.
