SAFETY / EXISTING CARDS
- No existing project file was deleted.
- No migration loop rewrites existing cards.
- No existing Card ID or activationCode is regenerated during startup/deployment.
- No existing owner, profile, URL or analytics record is overwritten by this Business implementation.

QUICK CAPTURE / LEADS
- Public Business profile includes Share Your Contact.
- Fields: Name, Phone, Email, Company, Optional Message.
- Consent starts unchecked.
- Privacy notice includes the 30-day retention statement.
- New lead documents use server createdAt/acceptedAt plus a 30-day expiresAt timestamp.
- Firestore security allows tightly constrained public CREATE only for activated Business cards.
- Reads/updates/deletes require JMX admin or the card owner.
- Owner dashboard shows active Leads only.
- Lead fields include status, notes, meeting notes, follow-up and days remaining.
- Manual deletion with confirmation.
- VCF download.
- CSV export.
- Expiring leads are hidden client-side after expiration.
- functions/cleanupExpiredBusinessLeads is included for backend deletion every 60 minutes.

EXTERNAL / DEPLOYMENT REQUIREMENTS
1. Firebase security rules must be published for Quick Capture to work safely.
2. Firebase Functions must be deployed for guaranteed automatic lead deletion. Scheduled Functions/Cloud Scheduler may require a billing-enabled Firebase/Google Cloud project.
3. AI Business Card Scanner is control/architecture-ready but requires a server-side AI/OCR provider and credentials. No API key is embedded in frontend.
4. Auto-Intro Email is control/architecture-ready but requires an email provider and backend anti-abuse logic. No fake sending is implemented.
5. Contact Map requires a chosen maps provider or privacy-safe map strategy before implementation; no geolocation is invented.
6. Apple Wallet requires Apple Developer certificates/pass type setup and server signing.
7. Google Wallet requires issuer/service-account configuration and verified integration.
8. Stripe production products, prices, charges, cancellation and production webhooks were NOT created or changed.
9. Public Business checkout consent UI is implemented, but durable purchase-consent records should be written by the authenticated checkout/backend once a real billing flow is selected.
