# QR integration tests (not deployed — `docs/` is excluded from Firebase Hosting and GitHub Pages)

`bash docs/qr-integration-tests/run-all.sh` — needs node 18+, python3 + opencv-python + numpy, Playwright + Chromium. No Firebase project, no network, no deploy.

- `unit.test.mjs` — the unified QR layer (`js/jmx-qr`): targetUrl identical to the original `qrShareURL()`, decoder (all 40 versions × 4 levels), logo safe zone for Card IDs of 1–64 characters, customization rules, Business Logo QR read only from the admin-only card document (profile injection ignored, URL allow-list), **storage.rules executed over a permission matrix** (admin / owner / other owner / anonymous × media folders × content types × sizes) against the original Prueba 8 rules, firestore.rules card-write check, **feature-control equivalence** (shared resolver vs. the previous script.js / dashboard.js resolvers on 77,760 combinations, and vs. `functions/index.js featureAllows`), and the SHA-256 manifest of protected files.
- `integration.test.mjs` — drives the real pages (`card.html`, `/c/…`, `/d/…`, `admin.html`, `dashboard.html`, `login.html`) with a GitHub-Pages-like server (`server.mjs`) and local Firebase mocks (`mock-firebase/`, fixtures in `fixtures.mjs`). Firebase Storage download URLs (`https://firebasestorage.googleapis.com/…`) are routed to an in-memory store **without CORS headers**. Every QR shown is screenshotted and decoded by two OpenCV decoders (`decode_image.py`); the text must be exactly the target URL.
- `scan_matrix.py` + `bench.html` — 288 QRs from the production engine at mobile (DPR 2/3) and desktop sizes, decoded clean and under 6 camera-like degradations (1,728 images).
- V2 additions — plan resolver (browser ↔ Cloud Functions parity, behaviour vs every previous surface, single source), static Auth / Wallet / NFC line fingerprints vs Prueba 8 (`fixtures/critical-lines-baseline.json`), intentional-edit reversal for protected files, dashboard delete/regenerate guard, legacy-plan saves, integrity counts before/after; inventory audit tests in `tools/inventory-audit/test/`; Firebase Emulator rules tests in `docs/emulator-tests/` (run separately).
- `results/` — written by each run (git-ignored, not part of the release zip).

What these tests do NOT cover (needs real infrastructure): Firebase emulator / production rules evaluation, real Google Sign-In, real Google Wallet API, physical NFC tags, real phone cameras.
